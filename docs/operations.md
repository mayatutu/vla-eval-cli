# 运行与排错

评测端与模型端使用同一版本代码及相同配置。模型管理通过 SSH 标准输入输出交互，观测/动作通过配置中的 ZeroMQ 地址传输，不依赖评测网页。

## 会话和次数

`load` 加载当前模型，`start` 开始一次实机评测，`finish` 提前结束后可评分，`pause` 中断且不计次。人工填写 outcome 和分数后导出；只有完整、已评分、已导出的试验计次。异常记录保留在 attempts 中。

`next` 在当前目标次数完成后切换模型。模型管理器仅停止自己创建并确认身份的子进程，不接管其他 client。若检查发现其他 GPU 模型进程或服务占用，应先确认其用途并由操作者退出，不能根据旧 PID 强杀。

Ctrl+C 请求软件中断；阻塞中的模型/RPC 调用可能要等待超时，不能替代物理急停。软件被强杀或控制服务失联时无法保证清理。此独立评测版保留启动复位，没有移植另一套原始 client 的结束复位逻辑。

## 常见错误

| 现象 | 检查 |
|---|---|
| SSH 失败 | 在终端确认地址、用户、认证、主机指纹和两端代码路径；程序不自动接受新主机指纹 |
| BusyError | 检查其他 client、模型服务和 GPU 进程；本管理器不会替你停掉无关进程 |
| contract mismatch | 比较两端完整 models.local.json 和代码版本，包括绝对路径、提示词和相机映射 |
| placeholder / missing asset | 填写所选 backend 的所有占位项，保留完整导出资产；运行 inspect |
| 相机无法打开 | 核对 USB by-path、三路角色、占用程序及设备供电；检查标定与序列号 |
| 机器人 RPC/控制失败 | 核对 NUC 服务和机器人状态；先解除设备故障，再由操作者重新开始 |
| 导出失败 | 保留 attempt 原始文件，检查剩余空间、ffmpeg/ffprobe、状态/相机采样，再用 retry-export |

## 数据含义

导出为 LeRobot v3：Parquet、三路视频、任务与 episode 元数据。30 Hz 是导出的时间网格；最近邻对齐可能重复使用真实状态或图像，记录中的复用标志、来源时间戳、RPC 延迟、错位统计应一起保留。不能把网格点数量解释为独立硬件采样次数。

动作日志表示发送给执行接口的目标，状态记录来自独立 RPC 读取。成功导出并校验后按原逻辑清理已登记原始 PNG；失败保留源数据。不要手动删除元数据或修改已导出的文件后继续复用同一导出路径。

使用 `--resume` 恢复时沿用模型顺序与已完成记录；未收尾试验标记为 interrupted，配置不一致则拒绝恢复。仓库不自动上传评测数据。
